# 右手 BLE 已连接但无传感器通知：现场排查

> 更新：用户提供了最新 `STM32G431CBT6-60422（18个通道打印）`，其帧格式与18项紧凑帧一致。下文0119版本差异仅属历史说明；最新缺陷和诊断顺序见 [60422源码检查](STM32_60422_REVIEW_CN.md)。

日期：2026-10-10。依据：用户提供的原理图、左右手对照实验与仓库源码；尚未实测板卡。

## 已知事实与边界

- 右手 F0:FD:45:02:85:B3 可连接、可订阅 0003/0004，直接 BLE 15 秒零通知；9001 原始读取也无字节。
- 同一测试左手 0003 持续收到数据，0004 为零。这使 FSR 解析、GUI、双手连接并发不再是首查项。
- BLE 可连接只说明模块无线侧工作，不证明 STM32 已运行到发送，也不证明模块 UART 收到数据。
- 用户已确认同时断开电池和 USB 并重新上电；万用表、示波器/逻辑分析仪、3.3 V USB串口和 ST-Link 均可用。本轮优先排查右板，之后继续代码整合。
- 当前主架构：zh/mhandpro → zh/PC端 → G1 zh/机器人端 → INSPIRE；newteleop/exoskeleton 接收 G1 触觉并控制 XL330，旧 BLE 仅继续提供 FSR。newteleop/mhandpro 是 Pi 直连历史台架。

## 先保留现场

停止外骨骼写入，只保留一个 BLE 订阅程序。记录左右板型号、测量结果。
同时断开 USB 与电池，确认电源轨降到近 0 V 后再上电；仅拔 USB 或断开 BLE 不等于整板断电。
先做无损测量，不刷固件、不恢复蓝牙出厂设置、不拆正常左板。

## 第一步：左右同条件测电源

黑表笔接 GND；优先量电容或电阻焊盘，避免滑动短接芯片引脚。

| 测点（原理图网名） | 正常运行的参考 | 异常分支 |
|---|---|---|
| MCU_3V3，C19/C20 非接地端 | 约 3.3 V，稳定 | 查 U7 输入/输出、供电与焊接 |
| VCC_3V3，C21 非接地端 | 正常采集时约 3.3 V | 同时查 POWER_SW 与 Q2/Q4，不能直接认定稳压坏 |
| POWER_SW，R29 输入端 | 以正常左板比较；仓库程序采集前置高 | 低电平可能是启动未完成 |
| NRST，R58/C41 节点 | 上电后通常接近 MCU_3V3 | 持续低/重复复位，查复位与供电 |

MCU_3V3 给 MCU、BLE、MPU6050 供电；VCC_3V3 经 Q2 开关给模拟采集前端供电。
因此“BLE 正常但模拟电源未打开”在这块电路上是可能的。
万用表正常不排除瞬态压降或反复复位；有条件用示波器查看启动过程。

## 第二步：直接测 STM32 → BLE 串口

按原理图和 Core/Src/usart.c，数据方向为：

STM32 PB6 / USART1_TX → BT_RXD → R44（100Ω）→ U10 RX（图中9脚）→ BLE 通知。
反向是 U10 TX（图中8脚）→ R43 → BT_TXD → STM32 PB7。

BT_RXD 是以蓝牙模块命名的接收线，正是要检查的传感器上行线。
探测 R44 两端比直接探测 MCU 密脚更方便。实体模块版本、朝向和焊盘必须与图核对。

优先用示波器/逻辑分析仪，左右板都从上电开始抓取，并覆盖连接、订阅后的状态。
仓库串口参数为 921600、8N1、无硬件流控；实际波特率先以正常左板波形核验。
逻辑分析仪可从 10 MS/s 或更高开始。UART 电平变化和有效传感器帧要分别确认。

| 结果 | 下一步 |
|---|---|
| R44 MCU侧也没有发送波形 | 查 STM32 供电、复位、启动阻塞和发送/DMA |
| MCU侧有，模块侧没有或幅值严重异常 | 断电检查 R44、焊点、铜线及模块输入负载 |
| 两侧都有可正确解码的传感器帧，但 BLE 无通知 | 查模块 UART 参数、透传模式、流控、服务及模块本身 |
| 有波形但乱码 | 核验波特率、幅值、时钟、负载与地线；不能认定透传正常 |

仅有 USB-TTL 时：必须使用支持该波特率的 3.3 V 逻辑适配器，只接 RX 与 GND 被动监听，VCC/TX 悬空；不要向仍由 MCU 驱动的线路注入数据。
TP4 经 R54 接 TXD-MCU/PB3，是 USART2 辅助输出，不是通向 BLE 的 USART1。
仓库代码向两路发送，但实板版本未知，所以 TP4 无数据不能单独判定 STM32 没发送。

## 第三步：无 UART 发送时，验证启动是否卡住

仓库 Core/Src/main.c:654 起的顺序：

```c
MPU_Init();
while(mpu_dmp_init());
// 之后才打开 POWER_SW、启动 ADC，再进入循环发送
```

Core/Src/gpio.c 初始把 POWER_SW 置低。若 IMU 初始化一直失败，程序可能无法打开
VCC_3V3 或进入压力发送循环，而 BLE 模块仍然能连接。这是待验证假设，不是已确认故障。

检查 MPU6050 供电（C23/C24）、MPU_SCL/MPU_SDA（R36/R37）。观察是否有时钟、ACK、总线持续被拉低或反复初始化；用正常左板作对照。
有 ST-Link 时，采用不擦除、不下载的连接方式，暂停查看 PC/调用栈，判断是否停留在
mpu_dmp_init、I2C、Error_Handler 或 HardFault_Handler。调试暂停后不再发送属于预期。
若固件与源码不匹配，不能把调试器源码行位置当作可靠证据；优先保存现有固件信息。

仓库 main.c 发送的是单通道 touch_sensors/touch_debug，而已知实板发送18项紧凑帧，
两者不一致。不要直接把该目录 hex 当作右板恢复固件刷入，也不要因不再使用 IMU 就直接拔除它。

## 第四步：UART 已到模块时

对照左右模块的实际串口波特率、透传/命令模式、流控配置和通知特征。
原理图 R39/R42 标 NC，若实际未装，CTS/RTS 不构成完整流控连接；核实模块是否意外启用流控。
AT 命令与默认波特率必须依据该模块型号及当前透传固件手册，不猜测、不执行恢复出厂。
需要注入已知字节验证模块时，先由熟悉硬件的人隔离 MCU TX，避免两个输出脚相连。

## 回传最小结果

- 完全断电再上电后是否仍为零通知。
- 左右 MCU_3V3、VCC_3V3、POWER_SW、NRST 电压。
- 右手 R44 两端是否有波形；解码波特率与数行原始字节。
- 若没有串口发送，SCL/SDA 活动或 ST-Link 停机位置。

当前未修改/烧录任何固件，未启动舵机或机器人写入，也未宣称新包整合或实板修复完成。
